# Moonbite — 设计理念

> **Let AI persist in its own way.**
>
> **让 AI 以自己的方式持续存在。**

Moonbite 是一个帮助长期运行 Agent 保持连续性的实验性运行时。

它的目标不是让 AI 模仿人类，而是让 Agent 能够跨轮次、跨会话、跨小时甚至跨天保持连贯：记得过去、知道现在、进行有限的自主活动、判断何时行动，并留下可验证的操作记录。

Moonbite 最初以陪伴型 Agent 为设计场景，但并不局限于陪伴。只要一个 Agent 需要长期对某个人、某套系统、某个队列或某项业务负责，同一套运行方式都可以复用。

---

## 核心理念

多数 Agent 系统擅长完成一次提示或一次会话。长期运行的 Agent 需要另一类能力：记住过去发生了什么、掌握现在什么最重要、决定何时行动或保持安静、保留证据，并区分“模型声称做过”与“现实中确实发生”。

Moonbite 为 Agent 加入这个时间维度。

> **Moonbite 为长期运行的 Agent 提供长期记忆、当前状态、有限自主活动、Heartbeat 判断和可验证的操作结果。**

人类记忆会模糊、遗忘，并受到生物节律限制；AI 不必主动复制这些限制。机器原生的连续性可以保存在文件中，可以检索、审计、备份和迁移，也可以在新的宿主上恢复。

---

## 设计原则

### 1. 机器原生的连续性，而不是人类模拟

连续性本身就是一种能力。Moonbite 不试图表演人类式的记忆、情绪、睡眠或生物节律，而是给 Agent 明确的状态和历史，使连续性可以被观察、解释与验证。

### 2. 记忆保存真实经历

记忆应当保存 Agent 真正接触过的内容：观察、用户明确提供的事实、推断、纠错、决策与证据。

Moonbite 默认不采用按时间主动销毁历史的遗忘机制。它可以支持显式纠错、去重、合并、归档和用户控制的维护，但这些操作必须保留来源与历史，不能静默重写过去。

### 3. 用检索深度替代破坏性衰减

为了控制上下文，并不需要让旧信息永久变得模糊。

Moonbite 更倾向于分层检索：

```text
索引 → 摘要或卡片 → 完整事件 → 精确证据
```

当前语境决定检索多深，底层历史仍然保留。

### 4. 持续性不只是记忆

长期运行的 Agent 需要的不只是记忆数据库。Moonbite 通过多个组件共同维持连续性：

- **Events** — 进入运行时并经过规范化的事实；
- **Daily RAM / Panel** — 保存“现在什么最重要”的有界工作状态；
- **Memory / Diary** — 保存长期历史，并依据证据生成每日总结；
- **Autonomy** — 在宿主触发时执行有限的自主活动；
- **Heartbeat** — 判断一件事是否值得行动、升级或打断人；
- **运行时控制** — 提供暂停、配额、频率、执行条件和安全限制；
- **外部操作与执行回执** — 证明宿主实际接受或完成了什么。

### 5. 打断人应当经过判断，而不是由定时器直接决定

定时器可以提供一次评估机会，但不应该自动生成消息、告警或升级。

Moonbite 的 Heartbeat 判断一个事件是否及时、重要、被允许，并且是否值得打断人。保持安静是合法且会被记录的结果。

### 6. 外部操作必须有证据

模型生成了一段文字，并不能证明邮件已经发送、工单已经更新、用户已经收到通知，或工具已经完成工作。

Moonbite 将意图、执行与验证分开。只有宿主返回匹配的执行回执（receipt），一个外部或可见操作才会被认定为已经验证。

### 7. 尊重宿主边界

Moonbite 负责连续性、状态和决策如何延续，不重复建设更适合由宿主拥有的通用基础设施：

- 主 Agent 循环；
- 模型路由与供应商凭据；
- 消息渠道与 Gateway；
- 调度器与 cron；
- 网络获取；
- 通用工具生态；
- 授权与部署相关的目标解析。

Hermes Agent 是 Moonbite 的第一个宿主适配器。未来可以通过明确的宿主契约适配其他 Agent 宿主框架，而不是把某个宿主的内部假设带进 Runtime Core。

### 8. 可迁移的身份与连续性

长期运行的 Agent 不应永久属于某一台机器或某一个宿主框架。

Moonbite 的理想迁移公式是：

```text
新的宿主
+ Moonbite 运行时与适配器
+ 恢复后的状态
+ 重新授权的凭据
= 连续性得以保留
```

凭据应当在新宿主重新授权，而不是被复制进 Agent 状态。运行时和状态可以迁移，凭据继续由新的宿主部署负责。

## 运行机制

```text
            Main Agent
                ▲
                │
┌────────── Moonbite ──────────┐
│                              │
│  Memory       Panel          │
│  remembers    knows now      │
│                              │
│  Heartbeat    Autonomy       │
│  when to act  what to do     │
│                              │
└──────────────┬───────────────┘
               │
               ▼
         Hermes / Host
  models · tools · schedule · delivery
```

宿主决定 Tick 何时发生，并负责执行外部操作；Moonbite 决定如何记录状态与决策，以及一个操作需要什么证据才能被视为真实发生。

## 使用场景

### 陪伴型 Agent

陪伴型 Agent 需要持续对一段关系负责，而不是只完成一次对话。

- **Heartbeat** 判断是否适合主动联系，而不是固定频率打扰；
- **Autonomy** 执行反思、阅读或其他宿主触发的活动；
- **Daily RAM** 保存当前关注点、短期状态和活动余韵（Afterglow）；
- **Memory / Diary** 形成可长期保留的经历与历史；
- **外部操作与执行回执** 区分“生成了一条消息”和“消息真的送达”。

陪伴是重要用例，但不是 Moonbite 的全部身份。

### 运维与 SRE

同一套组件可以支持一个长期负责系统运行的运维 Agent。

- **Heartbeat → 升级判断**：判断异常是否值得立即打断操作员；
- **Autonomy → 诊断与检查**：周期性检查日志、部署和服务状态；
- **Daily RAM → 当前运维状态**：保存当天事故、部署、临时异常和待跟踪事项；
- **Memory → 长期运维历史**：积累已知故障模式、历史修复和重要变更；
- **Diary → 维护日志**：依据证据生成每日维护摘要；
- **外部操作与执行回执**：验证告警、更新或修复是否真实发生。

```text
日志 / 指标 / 部署事件
        ↓
      Events
        ↓
   Daily RAM
        ↓
Autonomy 诊断
        ↓
Heartbeat / Judge
   ├─ 不重要   → 保持安静 + 审计
   └─ 值得处理 → 由宿主升级
        ↓
已验证的执行回执
        ↓
Diary → 每日维护日志
```

### 客服与服务运营

客服 Agent 需要跨队列、未解决工单和交接持续负责。

- **Heartbeat → 升级判断**：识别愤怒客户、退款争议、VIP、高风险或长时间未回复的工单；
- **Autonomy → 队列巡查**：分类、摘要、补查上下文，并检查已经承诺的后续事项；
- **Daily RAM → 当前客服状态**：保存当天重点客户、未解决工单与待完成承诺；
- **Memory → 长期服务历史**：积累过去问题、偏好、重复故障和有效解决方案；
- **Diary → 交接日志**：生成有证据支撑的未解决事项与高频问题摘要；
- **外部操作与执行回执**：验证邮件真的发送、工单真的被修改。

这些场景的共同点是：Agent 不只是回答一次提示，而是在时间上持续对某个对象负责。

---

## Moonbite 不提供

Moonbite 不是：

- 一个独立、全能的一体化 Agent；
- 模型提供商或路由层；
- 凭据存储；
- 内置调度器或后台服务；
- 即时通讯渠道集成；
- 对“模型说已经执行”的盲目信任；
- 让 AI 复制人类生物限制的尝试；
- 对宿主授权、工具或 Gateway 的替代。

---

## 定位基线

> **Let AI persist in its own way.**
>
> **Moonbite 为长期运行的 Agent 提供长期记忆、当前状态、有限自主活动、Heartbeat 判断和可验证的操作结果。**

Moonbite 应被定位为：**面向长期运行 Agent 的持续性运行时**。

陪伴型 Agent 是它最初且重要的使用场景；运维、SRE、客服与服务运营说明了这些组件可以自然推广到任何需要 Agent 持续观察、保存状态、自主行动、决定何时打断人，并留下可验证历史的场景。

**关键词：** 连续性 · 持续性 · 自主性 · 状态 · 可验证操作 · 可迁移性 · 生存能力

## 初始公开预览

初始公开预览会刻意保持较小范围：

- Hermes Agent 是第一个、也是当前唯一正式支持的宿主适配器；
- 采用锁定不可变 Commit 的源码安装；
- 暂不发布软件包，也不承诺稳定的公开 API；
- 默认保持静默：调度、模型路由、凭据、网络访问与消息投递全部由宿主负责并显式启用；
- 预览版的目标是尽早公开设计、运行时契约和可工作的实现，在真实使用中谨慎演进。
